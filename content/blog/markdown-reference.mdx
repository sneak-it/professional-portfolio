## Tables

GitHub-Flavored Markdown tables. The alignment row controls each column; Typography styles the borders.

| Feature | Syntax | Notes |
| --- | :---: | ---: |
| Table | `\| a \| b \|` | Needs the header separator row |
| Strikethrough | `~~text~~` | One tilde works as well |
| Task list | `- [x] done` | Renders a disabled checkbox |
| Footnote | `[^1]` | Definition can live anywhere in the file |

## Footnotes

GFM footnotes render a numbered reference that links to a definition list at the end of the post, with a back-reference arrow returning to the text.[^why] Multiple references to the same note collapse to one definition.[^why]

## Autolinks

A bare URL becomes a link without any bracket syntax: https://nextjs.org and www.typescriptlang.org both linkify. Email addresses do too: hello@example.com.

External links open in a new tab; footnote and heading anchors are fragments, so they stay in this one.

## Raw HTML is not a feature

Authored HTML is filtered, not rendered. The two elements below are in the body of this file and produce nothing at all:

<script>alert('never runs')</script>
<input type="text" value="never renders" />

An authored `<a>` or `<img>` does survive, but is rewritten to route through the same hardened components as Markdown links and images.

[^why]: Footnotes are the one GFM feature that generates its own heading and anchor ids, which is why the pipeline has to leave an existing `id` alone rather than overwriting it.
